# Siri Homestay website: Phase 1

The website, booking-enquiry system and owner admin for **Siri Homestay**, Joldal, Chikmagalur: five villas on a 4.28-acre estate.

- **Public site, built on a 3D estate made in code:** the villas, rooms, furniture, lawn, bamboo, trees and lights are generated by JavaScript (`src/world/`), modelled detail by detail on the owner's photographs. No photograph or film is published. The home page has a live 3D hero and a scroll-driven walk across the lawn and through a villa's sliding door to the bed; each stay has a room-entry camera flight and a guided 3D walk-through; the explorer flies between viewpoints with hotspots pinned to real objects. Every picture on the site is a render of the same world, so pages work without WebGL too. Plus stay pages, estate information, location, gallery, contact and the enquiry form.
- **Booking engine:** enquiries, holds, confirmations, villa allocation, owner date blocks and an availability calendar. Double-booking is prevented by the database itself.
- **Owner admin** at `/admin`: bookings, calendar, blocks, stays and villas, property and contacts, email log, activity log, settings.
- **Ready for Phase 2:** Airbnb and MakeMyTrip listing references, provider-independent channel adapters, sync records and idempotent import. **Nothing is connected in Phase 1, and nothing is shown as connected.**
- **No online payment** is collected.

## Run it locally

Requirements: Node.js 22 or newer. No compiler is needed: SQLite comes as a prebuilt binary, and `.npmrc` turns off install scripts.

```bash
npm install
npm run dev            # http://localhost:3000
```

On first start the app creates `data/siri-homestay.db`, seeds the property, five villas and the three enquiry contacts, and creates the owner account. The temporary password is printed in the console and saved to `data/INITIAL-ADMIN-LOGIN.txt`. Sign in at `/admin`; you'll be asked to choose a new password. Delete that file afterwards.

## Tests

```bash
npm test               # 14 booking-engine tests (Node test runner, in-memory database)
npm run test:e2e       # 41 browser checks on a fresh server: guest and owner flows, security, accessibility, the 3D estate
```

`test:e2e` uses Google Chrome. Set `CHROME_PATH` if it isn't at `/usr/bin/google-chrome`.

## Deploy

Any host that runs a long-lived Node process with a writable disk works: a small VPS (Hostinger, DigitalOcean, Lightsail), Render or Railway with a persistent disk, or similar. Serverless platforms without a persistent disk are not suitable for SQLite.

### Vercel

`vercel.json` and `api/index.js` run the site on Vercel: files in `public/` are served by Vercel's CDN and everything else by one function. Set `APP_SECRET`, `ADMIN_EMAIL` and `ADMIN_PASSWORD` in the project's environment variables. **Vercel functions have no persistent disk**, so on Vercel the SQLite database lives in `/tmp` and is reset whenever Vercel starts a new instance: enquiries and admin changes are not kept. Use Vercel for previews of the site; for live bookings, move the database to a hosted one first or run the app on a server with a disk.

1. Copy `.env.example` to `.env` and fill in `SITE_URL`, `APP_SECRET`, `ADMIN_EMAIL` and, for email, the `SMTP_*` settings.
2. `npm ci --omit=dev`
3. `npm start` (or run `server.js` under systemd or pm2), behind Nginx or Caddy with HTTPS, and set `TRUST_PROXY=1`.
4. Point `sirihomestay.in` at the server. Old WordPress addresses (`/resort/chickmagalore-homestay/`, `/features/media-gallery/` and so on) redirect to the new pages automatically.
5. **Back up `DATA_DIR`** daily. The whole booking history is the one SQLite file there (copy it while the app runs; WAL mode keeps the copy consistent if you use `sqlite3 data/siri-homestay.db ".backup backup.db"`).

Example systemd unit:

```ini
[Service]
WorkingDirectory=/srv/siri-homestay
EnvironmentFile=/srv/siri-homestay/.env
ExecStart=/usr/bin/node server.js
Restart=always
User=siri
```

### Email

Without SMTP the site works fully: enquiries are saved and visible in the admin, and the Emails page shows them as "not sent, email isn't set up". To send them, fill in `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS` and `MAIL_FROM`. With Gmail, use an App Password, port 465 and `SMTP_SECURE=1`. New enquiries go to every contact ticked "Gets emails" (Swetha and Ganesh by default), and guests get an acknowledgement.

### Admin password reset

```bash
npm run admin:reset-password -- owner@sirihomestay.in
```

## The 3D estate

Everything you see is generated in code: no photographs, films or 3D model files are loaded.

- `src/world/` builds the estate with three.js: canvas-painted textures (`textures.js`), materials (`materials.js`), furniture and props (`objects.js`), buildings (`buildings.js`), ground and pond (`terrain.js`), bamboo, trees and plants (`vegetation.js`), sky, sun and night lights (`lighting.js`), the site plan (`layout.js`) and the camera viewpoints and paths (`views.js`). `index.js` exposes `createWorld(canvas, options)`.
- `npm run build:world` bundles it to `public/js/world.js` (about 650 KB, about 170 KB compressed). The site loads it only when a 3D moment is about to be seen, and never with reduced motion or data saver on.
- `npm run render` renders every viewpoint in headless Chrome (`scripts/render-views.mjs`, about 20 minutes on a CPU) and turns the PNGs into the WebP renditions, placeholders and `public/media/manifest.json` (`scripts/build-renders.py`, needs `pip install pillow`). The manifest also records where each named 3D anchor falls in each picture, for the explorer's hotspots.
- The studio page `/world/studio.html?view=villa-bedroom` shows any viewpoint live in the browser (it is not indexed).

The buildings, rooms, furniture and planting follow the owner's photographs. No site plan was supplied, so the **arrangement** of the grounds (where each villa, the lawn, the courtyard and the pond sit) is illustrative, and the site says so in its footer.

The world module has no dependencies on the rest of the site, so it can be dropped into the React project as is: create a canvas in a component and call `createWorld`.

## Project layout

```
server.js                 entry point: migrate, seed, serve, housekeeping timer
src/config.js             settings from environment / .env
src/db/                   SQLite connection, migrations, seed data
src/domain/               reservations, inventory ledger, notifications, catalogue
src/channels/             Phase 2 boundary: adapter contract, registry, sync services
src/web/                  Express app, public and admin routes, auth, assets
src/views/                HTML templates (escaped by default)
src/world/                the 3D estate, generated in code (bundled to public/js/world.js)
public/                   CSS, JS, fonts, rendered pictures (public/media/renders)
scripts/                  renders of the 3D estate, admin password reset
tests/                    unit tests, end-to-end suite, screenshot helpers
docs/                     architecture, admin guide, QA report, content sources
```
